# Firefox開発版のビルドと確認

Firefox対応は未公開です。対象はデスクトップ版Firefox 140以降で、Android対応は対象外です。
Chrome Web Storeへ審査提出した1.5.0のZIP・`v1.5.0`タグは変更しません。Firefox対応を含む次版は1.6.0です。公開手順は [Firefoxへの公開](./firefox-publishing.md) を参照してください。

## ビルド

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run zip:firefox
```

Chromeは `dist/`、Firefoxは `dist-firefox/` です。FirefoxのZIPは `koan-plus-firefox.zip` で、本体と第三者のライセンスを同梱します。
Firefox用manifestは `background.scripts` を使い、`downloads.ui` を要求しません。共通の権限・接続先・コンテンツスクリプトなどがChrome版とずれた場合、ビルドを失敗させます。

開発時はFirefoxの `about:debugging#/runtime/this-firefox` で「一時的なアドオンを読み込む」から `dist-firefox/manifest.json` を指定します。一時インストールはFirefox終了時に解除されます。一般配布には別途署名・公開手続きが必要です。

## 自動テスト

```sh
npx playwright install chromium firefox
npm run test:ui
npm run test:ui:firefox
npx web-ext lint --source-dir dist-firefox
```

- 単体テストは、合成した認証情報とブラウザAPIで権限拒否・取消・再許可、保存済み情報の保持、MFA自動登録の停止を確認します。
- 画面テストはChromium・Firefoxで同じ合成データを使います。拡張機能としてのインストール・権限ダイアログ・実認証の検証とは区別します。
- `web-ext lint` の警告は個別に確認します。共用background内の `downloads.setUiOptions` は存在確認で回避します。Androidの最低バージョン警告を理由にモバイル対応を追加しません。バンドルの `innerHTML` 警告だけでXSSの有無を判定せず、React / DOMPurifyと入力処理を確認します。

## 実Firefoxでの確認（実施結果は別途記録）

1. 手動ログインで利用を開始し、自動ログインの任意同意を拒否してもダッシュボードを使えることを確認する。
2. 設定または初回案内で自動ログインを保存し、Firefoxの認証情報の利用許可を拒否すると保存・認証が進まず、許可すると進むことを確認する。
3. `about:addons` の「権限とデータ」で認証情報の許可を取り消す。新しいID・パスワード・TOTPの自動入力と、進行中のMFA自動登録が停止することを確認する。既に大学側へ送信した情報を取り消す機能ではない。
4. 保存済みの暗号化した認証情報が保持され、自動ログインの停止・削除ができることを確認する。再許可すると自動ログインを利用できるが、取消済みのMFA登録は設定画面から明示的に開始するまで再開しないことを確認する。
5. `technicalAndInteraction` の許可なしではお問い合わせURLにUser-Agentの事前入力値がなく、許可ありでは付くことを確認する。Chromeの従来動作も確認する。
6. KOAN/CLEの通常取得、セッション切れからの復帰、授業資料の個別・一括保存をChrome・Firefox双方で確認する。

大学アカウントの画面・ログ・認証情報をGitHubへ添付しないでください。結果はブラウザ・OSのバージョン、実施した項目、成功・失敗だけを記録します。

参考：[Mozillaのデータ同意仕様](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)、[一時インストール](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)。

## 2026-09-06 の大学実環境での追加確認

対象はPRの `248ed2f`、macOS上のFirefox 153.0（Playwright配布の検証用ビルド）です。Selenium / geckodriverで拡張機能を一時インストールし、通常の大学サーバーへ接続しました。通常配布版Firefoxおよび最低対応版140での確認とは区別します。

- 初回設定でFirefoxの認証情報の許可を拒否すると、認証設定は未保存のままとなり、必要な許可の説明が表示されました。
- 再度許可すると設定が保存され、ID・パスワードが大学の認証画面へ自動入力・送信されました。ワンタイムパスワードは利用者がブラウザへ直接入力しました。TOTPの自動入力およびMFAの新規登録・変更は実施していません。
- KOAN / CLEの両方でログイン状態の確認に成功しました。時間割・履修・変更・アンケート・掲示、CLEの科目・課題・メッセージ一覧等の更新完了状態を確認しました。最終的に掲示スナップショットと成績も取得され、各取得元の画面表示は正常状態、KOAN / CLEキャッシュの警告はなしでした。個々の学務情報の正確性を網羅的に照合した検証ではありません。
- Firefoxのアドオン管理画面で認証情報の許可を取り消した後も、保存済み認証設定とKOAN / CLEのキャッシュが保持され、再許可できました。再読み込み後のダッシュボードとキャッシュの復元も確認しました。進行中のMFA登録取消は実サーバーでは未検証です。
- 対応する授業の資料一覧は正常な0件となりました。この確認では実ファイルの個別・一括ダウンロードを実行できていません。
- 認証情報は専用ターミナルから一時プロセスへ入力し、プロジェクトの設定ファイルや検証ログへ出力していません。実画面・HTML・通信ログ・学務データを記録せず、結果の状態だけを確認しました。検証後、認証設定を削除し、専用ブラウザプロファイルと保存先の一時フォルダを削除しました。

### 見つかった確認事項

ワンタイムパスワードの入力待ちが長引いた間に、認証用タブが複数残っていました。`openLoginTab` は毎回タブを作成し、`ensureKoanLogin` は90秒の待機終了後に進行中タスクを解除するため、後続の同期が再試行すると既存の認証待ちタブを再利用できません。この両処理は認証情報の許可確認を除いて現行devと同一で、Firefox対応で新規導入された処理ではありません。

この実環境確認ではコード修正・push・マージは行っていません。後続の修正は以下に記録します。

### 認証待ちタブの回帰修正

KOAN / CLEごとの認証タブIDをメモリと `storage.session` に保持し、タイムアウト後の再試行やバックグラウンド再起動時にも同じタブを再利用するよう修正しました。再利用時はURLを変更せず、入力中のフォームを維持します。閉じたタブ・別サイトへ移動したタブは再利用せず、認証成功時に所有記録を解除します。タブ作成失敗後にも再試行できるよう、処理中タスクの解除範囲も修正しました。

- 元の `248ed2f` に対して、KOAN / CLEのタイムアウト再試行テストが両方失敗し、タブが2つ作成されることを合成データで再現しました。
- 修正後は新規の回帰テスト14件を含む単体テスト175件、型チェック、Chrome / Firefox両ビルドが成功しました。バックグラウンドの実コードを実行し、ブラウザAPIと時間・通信を模擬しています。
- 繰り返すタイムアウト、入力画面の保持、同時要求、タブ閉鎖・別サイトへの移動、バックグラウンド再起動、認証完了後の再認証、CLEの強制更新、タブ作成失敗とセッション保存機能の不調を確認しました。
- この修正に対する大学実アカウントでの再検証は行っていません。認証待ち上限とネットワーク確認間隔、既存の同期バックオフは維持しています。
