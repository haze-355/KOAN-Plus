# KOAN Plus デスクトップUI仕様

2026-09-05に整理した画面構成と操作の仕様です。その後の変更は [変更履歴](../CHANGELOG.md)、利用者向けの操作は [使い方](./user-guide.md) を参照してください。

## 共通の表示と操作

- デスクトップ拡張機能を対象とする。ヘッダーと左ナビゲーションを残し、ホーム中央・右カラムや各ページ本文の中でスクロールする。低いウィンドウではナビゲーションも必要に応じてスクロールできる。
- 左ナビゲーションは淡い背景と文字の太さで選択を示す。装飾的な縦線や強い色面を使わない。
- 未取得・取得中・一部取得・失敗・正常な0件を区別する。保存済み内容がある場合の同期問題は、ヘッダーの「同期の詳細」に集約する。
- 空状態の記号に装飾的な囲みを付けない。狭い授業詳細でも必要な補足を隠さない。掲示0件と検索結果0件は別の文言にする。
- 操作部品の色・背景・枠の変化は100ms、内容の表示は160msを基本とする。OSの「動きを減らす」設定では遷移をほぼ即時にする。
- 授業のホバー・選択と、成績のホバー・フォーカス・表ヘッダーには共通の淡い背景色を使う。キーボード操作のフォーカス表示は維持する。

## ホーム

中央の見出しは「課題・締切」「直近の休講・変更」（該当時）「CLEの連絡」「KOANのお知らせ」を同じ階層で表示する。

- 課題とアンケートは締切順。今日・今週を展開し、それ以降・期限未設定・期限切れは展開式にする。
- 休講・変更は今日から7日間のものを表示する。日付未確定の「今週」はその旨を示す。対応する授業がある行から、その授業を選択した時間割へ進める。
- CLEの連絡とKOANの掲示は別枠にする。CLEの未読メッセージを初期2授業、その下に授業連絡を新しい順に初期3件表示し、それぞれ続きを表示できる。日時や連絡事項の未読状態を推測で補わない。
- KOANは「重要」を初期選択とし、「最新」へ切り替えられる。掲載開始日の新しい順に初期3件表示する。未読という理由だけで古い掲示を先頭へ固定しない。
- 重要は行頭に橙色・太字で表示し、件名も太字にする。読み上げやホバーでは大学の指定と分かるよう補足する。
- 情報源は各見出しで示し、行ごとのKOAN/CLE表示は省く。公式リンクや掲示検索は見出し行の右側に配置する。
- 右カラムはカレンダーと選択日の授業。締切マーカーは残し、中央と重複する締切一覧は置かない。下部の余白は長い授業名・教室変更・補講の表示に使えるよう残す。

## 授業

時間割の科目を選ぶと右カラムを切り替える。独立した詳細ページには移動しない。学期の表示は「春・夏学期」「秋・冬学期」とする。

- 科目名・教室・曜日時限・教員・公式リンク・直近の休講や変更は、タブの外の上部に置く。その他の変更や履歴は展開式。
- 本文は等幅の「課題／連絡・掲示／資料」の3タブ。左右矢印・Home・Endキーで切り替えられる。別の科目を選ぶと課題タブに戻る。
- 課題は締切順。期限切れと提出済み・採点済みは別々に展開する。
- 「連絡・掲示」は選択した授業に関連するCLEとKOANを統合する。混在するため、情報源は件名下に表示する。
- 資料は選択した授業を対象に取得し、保存済み一覧を再利用する。個別・一括保存、再取得、進捗・失敗表示を備える。
- 授業が0件のとき、右側に授業の選択を促す案内を出さない。

## 掲示

「重要／要確認／未読／特典・謝礼／すべて」と検索・ジャンルを組み合わせる。表示件数／全件数の重複表記や、分類の長い説明を常設しない。

- 「重要」は大学の公式指定。候補判定より優先して表示する。
- 「要確認」は未読・新着・公式重要・件名・個別連絡などによる候補抽出。個人にとっての重要性や対応義務を確定しない。
- 「特典・謝礼」は件名から無料・割引・謝礼などを抽出し、研究参加や学内サービスの候補も含める。謝礼が不明なら未確認と示す。警告・終了・謝礼受領の事務連絡などを除外する。
- 本文の一括自動取得は既読状態に影響するため行わない。タイトル抽出には見逃しや誤検出があり得る。

## 設定とMFA

- 左カラムに自動ログイン・二段階認証・データ管理の操作をまとめ、有効・登録状態を各設定の横に置く。重複する状態一覧は置かない。
- データ管理は初期状態で折りたたむ。書き出し・削除・使用量確認は展開後に操作できる。削除には確認モーダルを維持する。
- 右カラムは認証情報の扱いの短い補足と、詳しい説明の展開欄。
- MFAの登録情報モーダルは、左にQR、右にキーと表示・コピー操作を配置する。大きな色面を使わず、コピーの成功・失敗をモーダル内に表示する。閉じて開き直すとキーを再び伏せる。
- 初回設定・変更・キャンセルの流れを維持し、認証情報の削除とキャッシュ削除を区別する。

## 成績

科目区分を展開すると、科目・学期・単位・評語の表を表示する。共通する詳細区分は表の上に1回だけ示し、区分が混在するときは区分列を使う。科目名は折り返し、数値は右揃えにする。空の表だけを残さず、未取得と0件も区別する。公式GPAの値を表示し、不足情報から通算GPAを推測しない。

## リンクと待機

有効な遷移先が分かっているKOAN/CLEリンクは、ログイン状態の事前照会を待たずに開く。未知の掲示URLだけ、認証状態を確認して遷移先を解決する。処理中は新しいタブに確認中と表示し、ポップアップが開けない場合は未読を更新せずエラーを表示する。

大学側の読み込み・認証や未知のURL検索には待機が生じ得る。同期処理の認証確認・通信上限・URL検証は維持する。

## 検証方法

合成データで変更した画面と共通部品の影響先を確認する。ライト／ダークを対象に、初回・保存済み・更新中・失敗・部分取得・正常な0件、長い科目名や情報量の増減、キーボード操作、画面内スクロール、モーダルの閉じ方とフォーカス復帰から、変更に関係するケースを選ぶ。共通レイアウトの変更ではホーム・授業・掲示・成績・設定を含める。実アカウントの認証・情報取得の検証は、自動テストとは区別する。

テストの実行方法は [CONTRIBUTING.md](../CONTRIBUTING.md)、取得処理の検証記録は [sync-recovery.md](./sync-recovery.md) を参照。過去のデザイン案は現在の実装仕様を示すものではない。
