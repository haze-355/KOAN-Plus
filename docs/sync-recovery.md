# CLEメッセージ同期の終端確認

2026-09-05の修正・検証記録です。現在の取得・再試行の仕様は [同期仕様](./sync-policy.md) を参照してください。

2026-09-05の実環境で、メッセージ一覧の末尾が `results: []` でも、`paging.nextPage` が現在のoffsetを指す応答を確認した。従来はこれを循環エラーとして扱い、カーソルを失って同じ取得を繰り返していた。

## 修正

- 空ページの返却offsetと次ページoffsetが要求位置と一致する場合、同じ位置を `limit=1` で追加照会する。追加応答も空でoffset・limitが一致し、終端または同じ位置を示す場合だけ取得完了とする。
- 追加照会で新しい科目があれば通常のページサイズへ戻して取得を継続する。通信失敗・不正な形式・時間上限の場合は保存済みデータと確認前の再開位置を保持する。非空の同一ページの反復は成功扱いしない。
- 旧版の既知の循環エラーと、その原因を上書きした再試行待ちに限り、更新されたページ処理を一度試せる。全体の1分間隔・排他制御は維持し、その後の失敗は通常のバックオフに戻す。データの削除は不要。
- CLEメッセージの失敗を、取得済み課題の失敗として表示しない。再読み込み後も保存済みの警告・未完了情報を同期詳細へ反映する。再試行待ちで原因を消さない。
- 手動更新が失敗・一部取得で終わった場合は続きの更新を待機させる。表示中・オンラインで待機時間を過ぎたら再開する。ログイン確認待ちや実行権の取得待ちは、通信失敗回数に加算しない。

## 検証

単体テスト121件、画面テスト31件、型チェック、本番ビルドに成功。合成データで終端確認・追加データ・不正応答・取得失敗・旧版の長いバックオフからの回復・自動ログイン無効時の手動再試行を確認した。

実環境の読み取り専用照会で、末尾の自己参照カーソルと1件照会による空の終端を確認した。修正ビルドを読み込んだ拡張機能でKOAN・CLEの同期が完了し、再読み込み後も成功状態が保持されることを確認した。実データ・セッション情報・画面記録はリポジトリへ保存していない。大学側の停止・通信断・権限のない情報について無条件に取得できる保証ではない。

## 成績取得と明示的な再試行

成績取得用のタブ内スクリプトを即時注入・分離した実行環境へ変更した。画面の読み込み完了待ちを避け、破棄・凍結されたタブは別の利用可能なKOANタブに切り替える。利用可能なタブがなければ前面を奪わず取得用タブを用意する。スクリプト応答にも上限を設け、期限後に実行が再開しても古いPOSTを送信しない。既存の通信上限・送信元／URL検証・成績表の構造確認・保存済み成績の保持を維持する。

加えて、失敗回数に応じた最大64分の待機が手動更新にも適用されていたため、手動では同期全体の待機を最短1分に短縮できるようにした。自動再試行には従来のバックオフを適用し、手動・自動のどちらもタブ間の排他と各取得処理の通信制限を守る。認証前の失敗にも最小1分間隔を適用する。

単体テスト130件・画面テスト35件・型チェック・本番ビルドに成功。合成応答で即時注入、凍結タブの回復、応答のないレンダラー、期限後のPOST抑止、長い失敗待機からの手動回復を検証した。実サーバーでの取得成功は自動テストとは別に確認する。

実環境では修正ビルドの成績画面から手動更新を実行し、「成績を同期中」から最終更新の表示へ変わり、保存済みキャッシュより新しい更新時刻になったことを確認した。元の25秒エラーを再現して原因を確定した検証ではない。待機制御・取得処理を修正した後に、実サーバーで更新に成功したことを確認したものである。実アカウントの具体的な更新時刻は公開記録に含めない。
