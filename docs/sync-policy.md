# データ更新の仕組み

[READMEに戻る](../README.md) · [English](./sync-policy.en.md)

利用者向けの更新・再試行手順は [使い方](./user-guide.md#更新が止まったとき) を参照してください。以下は開発者向けの仕様です。

KOAN Plusは、情報の変わりやすさと取得時の通信量に応じて、保存済みデータを再利用する期間や取得範囲を分けています。

- **自動同期**: 自動ログインが有効な場合、起動・画面切り替え・画面への復帰・再接続と、表示中の30秒ごとのローカル確認で、再確認の時期を迎えたデータだけを取得します。30秒ごとに大学サーバーへアクセスするわけではありません。非表示・オフライン中は新しい自動同期を開始しません。
- **手動更新**: 新着掲示・今週の授業変更・CLEの課題一覧とメッセージは直近1分の取得結果を再利用し、それより古ければ確認します。時間割や履修科目などの長いキャッシュは維持します。通信制限中も保存済みデータを使え、必要な更新は画面が表示されオンラインの間に自動で再試行します。
- **更新の重複防止**: Web Locksで複数画面からの同時更新を防ぎ、他の画面が保存した結果を取り込んでから更新の必要性を判定します。各取得処理にも通信間隔の制限と、有効期限付きの実行権（リース）を設けています。
- **認証確認の共有**: KOANポータルの確認が同時に要求された場合は、実行中の1リクエストを共有します。同じCLEタブでのAPI利用可否の確認も同様です。完了結果はキャッシュせず、次の確認では改めて通信します。
- **認証タブの再利用**: KOAN / CLEごとに拡張機能が開いた認証タブをブラウザのセッション内で記録します。待機がタイムアウトしても、次の同期では同じタブを再利用し、入力中のワンタイムパスワード画面を再読み込みしません。タブを閉じた場合や関係のないサイトへ移動した場合は作り直します。認証完了後は再利用の記録を解除します。待機時間の上限と同期失敗時のバックオフは維持します。
- **KOANの認証待ち**: 初回のログイン状態はすぐに確認し、未認証ならポータル確認を5秒間隔で最大90秒続けます。認証タブが閉じられたかどうかは、1秒間隔で端末内で確認します。
- **キャッシュの活用 (KOAN)**: 今週の授業変更情報や未読掲示は短い間隔、アンケート一覧と現在の時間割は中程度の間隔、8週間先までの時間割・授業変更情報は6時間、履修科目マッピングは1日1回のキャッシュを使用します。
- **キャッシュの活用 (CLE)**: メッセージサマリーは通常15分、課題一覧は10分、コースマッピングは24時間を目安に更新します。また、個々の課題のステータス詳細（提出済み、採点済み等）の取得は個別リクエストが発生するため、状態ごとに長い更新間隔を設けています。
- **CLE課題の詳細確認**: 期限が近く未完了の課題を優先的にチェックします。通常は締切が過去30日から今後14日までの課題と、期限未設定の課題を対象とします。提出済みの課題は採点を追跡するため、この期間外でも対象に残します。採点済みは7日、提出済みは6時間、期限切れは24時間を目安に再確認します。未確認の対象課題が残る間はキャッシュ全体を完了扱いにしません。
- **CLE連絡事項の段階取得**: 現在履修中の科目だけを対象に、表示中または最近利用した科目を優先して1回最大4科目ずつ取得します。科目ごとに2時間のキャッシュを持ち、未取得科目が残る間は次回更新で巡回を続け、取得失敗時は以前のデータを保持します。
- **掲示一覧の同期**: ジャンルを巡回して一覧を保存する処理を、スナップショット同期と呼びます。自動同期と掲示画面の **[更新]** のどちらも、取得完了後は6時間のキャッシュを再利用します。初回は一覧を取得し、2回目以降はジャンルごとに既知の掲示だけのページが2ページ続いた時点でページ送りを停止します。途中で中断した場合は、保存済みの掲示と今回取得できた分を保持し、一部取得として扱います。
- **掲示本文の自動取得をしない理由**: 掲示の詳細を開くと既読状態が変わるため、本文の事前取得（プリフェッチ）は行いません。
- **表示と再検証の分離**: キャッシュが期限切れでも保存済みデータを先に表示し、更新結果が返ってから差し替えます。同一URLの実行中リクエストは共有し、失敗が続く場合は対象ごとに指数バックオフを適用します。HTTP応答の構造が期待と異なる場合やページングが完了しない場合は、空データで上書きせず「一部未取得」として以前のデータを保持します。
- **成績取得の制限**: 自動同期は6時間を目安とし、成績画面の **[更新]** は直近1分の結果を再利用します。失敗時は保存済みデータを保持し、認証段階の失敗も含めて再試行間隔を延ばします。

掲示同期にはページ数・実行時間・通信間隔の上限があり、本文を自動で開くことはありません。自動ログインを停止すると定期的な自動同期も停止し、更新ボタンからの操作を利用できます。

掲示同期の再開時は、現在のキャッシュ形式で取得が完了し、6時間以内のジャンルを省けます。未完了ジャンルは先頭から走査します。時間割・掲示の上限到達後に、解析しない次ページを取得することはありません。

## 明示的な再試行

手動の再試行では、同期全体の待機を最短1分に短縮します。ただし、各取得処理の通信制限も適用されるため、常に1分後に通信できるわけではありません。掲示一覧のスナップショット同期は、前回の試行から最低10分、取得完了から6時間の間隔を空けます。ほかの画面で処理中の場合も、その終了を待ちます。

自動再試行は、失敗回数に応じて待機時間を延ばします。手動・自動のどちらも、タブ間の同時更新防止と取得処理ごとの待機条件を守ります。

実装は [sync.ts](../src/sync.ts)、[koan.ts](../src/koan.ts)、[cle.ts](../src/cle.ts) を参照してください。修正時の検証記録は [sync-recovery.md](./sync-recovery.md) にあります。
